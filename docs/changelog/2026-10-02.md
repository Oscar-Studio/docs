# memoquest 首屏改成提问页，修复登录后无限请求，画布固定为纯色

[memoquest](https://memoquest.oscarstudio.cn)（[产品文档](/ai/memoquest)）今天动了三件事：首屏改成了**先提问再讲课**的形态；修了一个上线以来一直存在的**资源泄漏**；**画布不再跟随用户自定义背景图**。

## ✨ 首屏改成「问一句」

打开 memoquest 不再是黑板加演讲稿等着你填输入框，而是**先把问题摆在页面正中**：

> **小夏同学**，今天想学点什么？

下面一个大输入框，再下面两枚按钮「讲解」「编排」——分别决定**写稿**和**板书**用哪个模型，点开就地浮出一层列表挑，不用再点进一个居中的弹窗。选完发问，**提问区整块平滑滑到屏幕底部并收窄**，黑板和讲解区从下方浮现出来开始讲课。

### 挑模型不再套一层弹窗

原先是页面顶部一条「模型」栏，点开是覆盖全屏的模态。现在提问区本身就在屏幕中央，再套一层模态会把刚做好的"一眼看清在选什么"打散，所以改成两枚胶囊按钮就地展开。列表按**免费 / 计费**分组不变，价格徽标不变。

额度摘要（本次问答大概花多少、占今日多少、还剩多少）从常驻的顶部一条挪进了浮层底部——它只在**正在挑模型**的时候才需要看，常驻会在学生真正要提问的地方抢注意力。

### 名字从哪来

标题里的用户名复用**已经在请求**的 `GET /api/user`（额度和用户名在同一次返回里，不额外发请求），另外首屏会先从本域缓存里同步读一次，保证**第一帧就带名字**，不会先显示"今天想学点什么？"再跳成有名字。

### 顺手修掉的一个会误导人的地方

模型清单还没加载完（或加载失败）时，胶囊按钮原本显示「约 0」——这会被直接读成"不花钱"，而它真实的含义是**还不知道**。现在显示「读清单…」，浮层底部也恢复成"正在读服务端清单…"。

## 🐛 登录后陷入无限请求

页面原本有一段"登录后拉取剩余额度"的逻辑，写法上它每次渲染都会重新执行，而它写入的是一个**每次新建的对象**。React 只在值完全相同时才会跳过重渲染，新对象永远不相等，于是：

```
渲染 → 拉额度 → 写入新对象 → 必然重渲染 → 拉额度 → ……
```

一旦登录成功就再也停不下来。表现是手机明显发烫、耗电变快，长时间开着还会一直占着网络。功能本身看起来"能用"，所以很难被察觉——它不是把界面搞坏，而是安静地烧资源。

### 修复前后的实测

用无头浏览器在**线上生产构建**上直接数请求：

| | 修复前 | 修复后 |
|---|---|---|
| 观测时长 | 8 秒 | 30 秒 |
| `GET /api/user` 次数 | **747 次**（≈93 次/秒） | **2 次**（登录时各一次） |
| 相邻间隔 | 9–13ms，无任何退避 | 之后 28 秒零增长 |
| 是否持续增长 | 是，直到关页面 | 否 |

剩下的 2 次是正常的：一次来自页面挂载，一次来自登录 SDK 的登录态通知事件。屏蔽该 SDK 后恰好只剩 1 次，确认了这一点。

### 一个容易踩的坑

这个循环**不会**触发 React 的 `Maximum update depth exceeded` 警告——因为每一轮都真的 `await` 了一个网络请求，控制权会交还给事件循环，React 的循环检测也就没被触发。

所以这类"看起来完全正常"的死循环，只能靠**数请求的频率和间隔**来判断：间隔稳定在几十毫秒且**没有任何退避**，就是循环；几百毫秒且有抖动，则是正常的定时轮询。

### 修复方式

两处一起改，互为保险：

1. 依赖数组里只保留状态 setter（它的身份跨渲染稳定），不再依赖每次渲染都会重建的回调
2. 拉回来的额度值没变化时，把**上一次的引用原样还回去**，让 React 真正能够跳过重渲染——即使将来依赖又被改坏，也只是多发一次请求而不会自激

## ⚡ 画布不再跟随用户自定义背景图

之前 memoquest 会在登录后显示你在 Oscar Studio 设置的**自定义背景图**（以及对应的暗色遮罩）。现在**memoquest 始终使用自己的纯色画布** `#faf9f5`（暖米色，DESIGN.md 定的色）。

其他站点（工具站、教学工具站、主站等）**不受影响**——你设置的那张背景图在那些地方照常显示。

### 这不是 memoquest 自己画的

背景是共享登录 SDK 干的：`user-button.js` 读到用户配置里有背景图之后，会往页面里塞两层 `position:fixed` 的全屏层，再把 `body` 的背景改成透明。这套机制对所有引入该 SDK 的子站一视同仁。

memoquest 的处理方式与 `tools/`（studio 主题）、`teaching-tools/`（notebook 主题）**保持一致**：用 CSS 压住，而不是改共享 SDK——所以不需要动 API，也不会影响别的站点。

### 一个 CSS 层级的细节

SDK 写的是 `document.body.style.background = 'transparent'`，那是 **inline style**。层叠里普通规则压不住 inline style，只有作者的 `!important` 排在它前面——所以抢回画布色的那条 `background: #faf9f5` 必须带 `!important`。规则写在样式表里、SDK 还没执行到之前就已生效，因此不会出现"背景图先闪一下再消失"。
